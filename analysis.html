Plugin으로 기획한 프로젝트 진행상황을
모니터링하고 검증하는 앱

프로젝트 단위의 기획 문서의 진행 단계, 문서 간 연결, 누락과 오류를 모니터링할 수 있도록 화면으로 보여준다.

문서는 Plugin에서 만들고 수정한다. Studio는 결과를 읽고 점검하며, 수정이 필요하면 점검 결과와 다음 작업을 AI 코치에 전달한다.

Reading the product

1.0을 설명하는 네 가지 문장

① 화면은 파일보다 “다음 판단”에 가깝다

9단계를 다음 행동이 달라지는 다섯 구간으로 묶는다. 퍼센트 대신 현재 단계와 근거를 보여주고, 오류와 미결 결정을 먼저 알린다.

② 같은 원본을 여섯 관점으로 읽는다

여섯 화면은 데이터 분류가 아니라 실제 업무 순서를 따른다. 모두 같은 프로젝트 파일을 다른 관점으로 읽는다.

③ 추정하지 않는 것이 기능이다

문서 ID·출처·참조·버전만 근거로 삼는다. 근거가 없으면 추정하지 않고 “측정할 수 없음”으로 표시한다.

④ 안전은 확인창이 아니라 경계로 만든다

화면의 파일 접근을 막고 실행 작업을 고정한다. 자동 검증의 쓰기 대상도 세 파일로 제한하며, 이탈한 변경은 실패·복구 처리한다.

제품 형상의 강점과 남은 질문

관점1.0에서 확보한 것다음에 풀어야 할 것
제품 경계Plugin은 생산자, Studio는 소비자. 두 제품을 독립 버전으로 운영Plugin 릴리스마다 입력 계약 영향 판정을 지속
기획자 경험상태 확인 → 근거 탐색 → 검증 → 코치 인계의 닫힌 루프같은 UX 리뷰가 화면설계와 품질에 겹쳐 보이는 문제 정리
협업 확장도메인·버전별 화면설계와 로컬 버전 묶음개발자가 받는 핸드오프 단위와 전달 상태를 제품화
신뢰내 컴퓨터에서의 분석, 실행 내용 식별값, 변경 감시, 실행별 복구 기록Studio 버튼으로 AI 코치의 특정 작업을 여는 연결(딥링크)에서 요청 문구가 유실되지 않는지 지속 검증
ReleaseKit Studio 1.0은 “AI가 기획을 대신한다”는 제품이 아니다. 사람이 만든 근거를 잃지 않은 채, AI와 일하는 기획 과정이 끊어지지 않게 만드는 제품이다.
